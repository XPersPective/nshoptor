## Objective
"Tamamlanmış olana geri alabilir miyiz; fişte listede olmayan şeyler de alınmış olabilir." (user 2026-10-18). Preserve recorded prices and allow explicit reopening. Accepted receipt products must appear in the canonical list; receipt acceptance never completes shopping.

## Steps
1. `ListStatus` permits completed→shopping. `ListRepository.changeStatus` does read/guard/write atomically and returns unchanged for same status so repeat events preserve timestamps. Reopening clears completedAt while preserving all item, entry, observation data.
2. `ListDetailScreen` derives editability from loaded ListStatus; completed details offer existing localized continueShoppingLabel in the more menu with key detail_continue_shopping. Reuse busy guard/saveFailed for async transition. Refresh the existing detail after success so editing and receipt action are reachable. Archived details stay read-only.
3. In `ReceiptReviewController._commitOnce` existing transaction, reject completed/archived target lists (must explicitly reopen). For accepted unlinked positive-quantity non-discount product rows, use existing ItemRepository.addItem with price:null and their actual quantity, default piece; link the resulting item to recordPurchase. Discount/refund rows stay separate purchase adjustments. Do not mutate ReviewLine IDs before transaction success; no new schema/dependency. Preserve _commitFuture retry behavior and linked purchase replacement.
4. Update existing status/repository/unified-list and receipt tests for the new product-row behavior; prove reopen→edit→complete preserves entries/price observations and restores reporting once, zero-price receipt product checked, discount/refund handling, cancellation before commit, rollback and concurrent same-controller commit. Trace existing callers, don't patch only one screen.
