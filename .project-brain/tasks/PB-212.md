## Objective
Evolve Drift schema cleanly from v5 to v6 to persist durable batch receipt queue sessions (`queued`, `processing`, `ready`, `duplicate`, `error`, `converted`), tighten compact JPEG encoding for low-bandwidth Vision AI uploads without losing receipt text legibility, and implement deterministic `(store + date + time)` duplicate detection against existing lists and receipts without auto-mutating data (`C-004`).

## Steps
1. Update `lib/data/db/app_database.dart`:
   - Add `queueState`, `queueError`, `convertedAt`, and `duplicateOfListId` (`onDelete: KeyAction.setNull`) to `Receipts`.
   - Bump `schemaVersion => 6` and implement `onUpgrade (from < 6)` adding columns safely and backfilling existing reviewed/attached rows to `queue_state = 'converted'` while creating an index on `receipts (list_id, queue_state)`.
   - Run `dart run build_runner build --delete-conflicting-outputs` to regenerate `app_database.g.dart`.
2. Tune `lib/features/receipts/ai_image.dart`:
   - Downscale receipt/label photos cleanly to legible AI resolution (<= 1280px longest edge) with tight byte target (`<= 350 KB`) so server Vision AI costs stay low while product lines, totals, and timestamps stay sharp.
3. Implement `lib/features/receipts/receipt_dedup.dart`:
   - Pure + DB query helper checking candidate `(storeName, printedAt)` against existing `ShoppingLists` and converted `Receipts` (normalized store fold + `±15 minute` tolerance, or calendar-day check if midnight/time-missing, plus `identityKey` match).
4. Update `lib/features/receipts/receipt_draft_repository.dart` and `receipt_repository.dart` to support queued/unconverted session CRUD (`watchTrayReceipts`, `countPendingTray`, `updateQueueState`, `deleteReceiptSession`) cleanly inside atomic transactions.
5. Add comprehensive unit/migration tests (v5 -> v6 upgrade test, JPEG budget test, `(store + date + time)` dedup edge-case tests).
