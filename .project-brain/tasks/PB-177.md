## Objective
The user requires correct invoice/receipt reading before release. Native run 40431703546 read the real CORD photograph's TOTAL as TOT AL and incorrectly counted it as a fourth product. Recognize only a whitespace-split entire TOTAL label followed by a strict amount, without inventing numeric values or merchant identity.

## Steps
1. Normalize the narrow split TOTAL label after readingRows geometry reconstruction, shared by parser and document metadata. Preserve raw scan fragments and amounts.
2. Require whitespace/colon delimiter and an entire numeric amount with optional already-supported currency; never rewrite product names, signs, malformed tokens or O into zero.
3. Replay actual native OCR rows J.STB PROMO/17500, Y.B.BAT/46000, Y.BASO PROM/27500, TOT AL/91000, CASH/910O0 with original top/left coordinates in a regression. Preserve incomplete-header approval gates, discount-once behavior and durable decode/replay.
4. Detect explicit currency on original geometry-reconstructed rows before selecting the narrow label normalizer. Use the existing detector/fallback/ambiguity behavior and no recursive readingRows call. Regress foreign caller context versus explicit IDR/TRY/KWD receipt currency, retaining identical metadata/completeness/raw evidence after encode/decode.
