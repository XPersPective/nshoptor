## Objective
Premium readable reports require fixing confirmed native clipping. Native40435341913 generated9pages but still splits products68/111 and omits repeated headings; CSS alone failed. Provide escaped structured fragments from the same report snapshot so UIKit can measure whole-row pages (PB-180). Preserve financial values, ordinary HTML and Android text/export contracts.

## Steps
1. Refactor existing HTML builder into a small immutable report-fragment value plus existing buildShoppingReportHtml compatibility wrapper. One shared escaped source creates fullHTML and structured fragments; no duplicate template implementations. Keep fixed table-layout/column geometry, fonts/styles/locale/RTL/CSP/escaping. Per-section totals once; aggregate only zero/multiple lists.
2. Version1 channel schema EXACT: {version:1, start:String, end:String, sections:[{start:String, rows:List<String>, end:String, footer:String}]}. Root start contains doctype/style/openbody/brand/title/disclaimer; root end closes document. Section start contains section heading/metadata/open table/thead/open tbody. Section end closes tbody/table/section; footer contains only that list total and, for last section, aggregate if multiple lists. FullHTML = root.start + each(section.start+rows.join()+section.end+section.footer) + root.end. Empty document uses one section with empty start/end/rows and aggregate footer. Footer outside section is valid HTML. All content remains escaped from source.
3. ReportExportService builds fragments once and sends fullHTML as before; include pagination map ONLY on iOS renderPdf via platform check, leaving Android html/text and CSV unchanged. No production UI changes/dependencies/migrations/monetary recomputation. Tests can override target platform with restoration.
4. Regress fullHTML/fragment parity, one-row intact structure/escaped malicious text, same monetary strings, header/metadata per section, zero/one/multiple totals and iOS-only payload/Android absence. Keep original export success/cancel/error contracts.
