## Objective
Implement F15/F20 safely: deleting one receipt must remove only its own products/purchases, preserve other receipts and manual products, and permit re-import. Replace the timestamp ownership guess identified in the 2026-10-29 handoff.

## Steps
1. Add nullable PlannedItems.createdByReceiptId in schema v5; migrate existing rows as unknown, never infer ownership from dates (ADR-009).
2. Set provenance only when creating receipt-owned rows in receipt_capture_flow.dart and receipt_review_controller.dart; preserve it when a draft becomes reviewed.
3. In ReceiptRepository.delete, remove explicitly owned rows only without other purchases; include unpriced partial rows. Preserve manual and unknown legacy rows.
4. Validate, order and remap this relation in backup_repository.dart for merge/separate import; preserve absent provenance from older backups.
5. Test nonempty migration, legacy backups, round trips, cross-list rejection, second receipt preservation, partial deletion and re-import.

## Acceptance
- [ ] [machine] Receipt deletion/re-import preserves manual and second-receipt data regardless of timestamps and removes owned unpriced partial rows.
- [ ] [machine] Nonempty v4 and earlier migration keeps monetary values/relations; old rows have unknown provenance and no FK violations.
- [ ] [machine] Merge/separate backup restores ownership to the correct receipt; malformed/cross-list relations reject atomically; legacy backups remain readable.
- [ ] [architecture] Nullable set-null provenance replaces timestamp inference; no purchase before approval, API/model change, or UI change.
