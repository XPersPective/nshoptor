## Objective
Support the authorized iOS release: TestFlight and App Review Sandbox purchases must work through the client's single production endpoint when the server explicitly enables Sandbox, without weakening full Apple proof verification or paid quota identity.

## Steps
1. In server/src/apple.js, preserve Production-only default and explicit Sandbox-only two-flag configuration; permit Production then full Sandbox verification only when APPLE_ALLOW_SANDBOX=1.
2. Bind status hostname, response identity/environment, current transaction and renewal verification, and canonical quota identity to the verifier that accepted the submitted proof. Never switch after status API failure.
3. Extend actual official-verifier cryptographic and local workerd tests for default rejection, opt-in routing/identity, Production compatibility, forged/tampered/foreign proof, revocation, renewal isolation and unknown environments.
4. Document server-only deployment switch, exact trust boundaries, Sandbox quota abuse limits and untested live dependencies. Android/trial quota remains unchanged.
5. Follow Apple's optional StatusResponse appAppleId schema: require an exact configured ID in Production; fully verified Sandbox may omit this one envelope field, while any present field must match exactly. Verify absence success and malformed/mismatched presence rejection in Node and workerd.
