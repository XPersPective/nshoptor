# PB-165 — Build and verify signed iOS candidate with existing publisher credentials

Domains: ios-release, signing

## Objective
Create an exact-commit, manually dispatched iOS signing pipeline that builds and verifies an App Store candidate with the existing private publisher certificate, profile, AdMob IDs and App Store Connect API key. The default action validates a signed IPA locally in CI; the optional upload action submits it to App Store Connect for processing only. It must never trigger TestFlight distribution, App Review submission, or public release.

## Steps
1. Add `.github/workflows/ios-release.yml` with only `workflow_dispatch` and `workflow_call` triggers, so the registered iOS dispatcher can invoke the reusable workflow from the selected feature commit. Use `macos-15`/Xcode 26.3, exact 40-character `expected_sha`, optional `upload` defaulting false, required reusable-workflow secrets, read-only contents permission, serialized `ios-release` concurrency, and a 40-minute timeout. Verify the checked-out SHA and candidate version before exposing signing secrets.
2. Add `tool/ios/prepare_release.py` to keep raw signing/API material under `RUNNER_TEMP`, validate the App Store profile and four exact non-test iOS AdMob identifiers, write the app ID to the ignored `AdsConfig.xcconfig`, unit-only Dart defines, profile metadata, ASC key and manual App Store Connect export options, then clean private files and the installed profile on all outcomes.
3. Add `tool/ios/configure_signing.rb` to set manual distribution signing only on Runner target Debug/Release/Profile configurations. Keep the generated project mutation ephemeral and uncommitted.
4. Build one IPA, verify codesign, team, bundle ID, version 1.3.1/build 19 and exact embedded profile, then report only candidate SHA-256 and byte size. When `upload=true`, run `xcrun altool --validate-app` followed by `--upload-app`; do not distribute or submit for review.

## Acceptance
- [ ] Workflow has only `workflow_dispatch` and `workflow_call`, verifies exact source SHA before any signing/ASC secrets, and uses the specified runner, Xcode, permissions, concurrency and timeout.
- [ ] P12/profile/ASC key/Ads JSON and generated signing/export files stay under runner temp; no secret values or private-key material are printed; keychain, installed profile and temporary keys are cleaned on success and failure.
- [ ] Profile is App Store distribution for team `53X3279WA3` and bundle `com.crazypenguin.nshoptor`, unexpired, with `get-task-allow=false` and no device list or all-device flag. Ads JSON has exactly the four required iOS keys and rejects Google test IDs.
- [ ] Only Runner target build configurations receive manual signing, expected team, profile name and Apple Distribution identity; no project-file mutation is committed.
- [ ] Exactly one exported IPA passes deep/strict codesign, expected team, bundle ID, version 1.3.1/build 19, and embedded-profile equality. Summary contains only SHA-256 and size.
- [ ] Optional upload path validates and uploads to App Store Connect only; it does not enable TestFlight distribution, App Review, or public release. Only the distributable IPA and sanitized verification receipt are retained as a one-day artifact for private local download; no credentials or source archive are uploaded.
