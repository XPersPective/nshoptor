## Objective
User requires professional complete reports. Confirmed native9page PDF still clips rows68/111 after CSS probe and lacks repeated headers. Use actual UIKit measurements to keep rows intact and repeat context/headings, preserving money/Unicode and explicit cancellation/deadline/failure states.

## Steps
1. Implement optional iOS renderPdf pagination version1 contract exactly as PB-179 (read its schema). Strictly validate version/types/nonempty sections<=500, total rows<=10000, nonempty row strings, and aggregate UTF16 budget<=2,000,000 INCLUDING fullHTML+all fragment strings; reject unknown versions/malformed data before pending job. No HTML string parser, third-party dependency or print-method/Android changes. Keep existing unstructured renderPdf fallback for old callers.
2. New private per-job incremental state machine stays on main queue and yields between EACH UIKit measurement and EACH page rendering. Original bridge generation, one pending result, app-active checks, dispose/background cancellation and30s systemUptime deadline remain; complete/cancel clears job with no late callback/leak. Check generation/activity/deadline before AND after every operation; individual UIKit call remains soft-deadline/uninterruptible. Document this limit, do not pretend dispatch timeout preempts synchronous UIKit.
3. Per section, first measure all remaining rows WITH final footer using fresh fixed ReportA4PageRenderer and UIMarkupTextPrintFormatter. If onepage, retain exact measured renderer and accept final chunk. Otherwise binary-search largest prefix of whole rows WITHOUT footer fitting onepage (fixed tablelayout/header/column widths justify monotonicity). Repeat root/section/table headers in every candidate. If no single row fits, return explicit report_too_large; never draw just page0 of multipage candidate. If all rows fit without footer, render them, then measure footer-only page with repeated context. Empty sections/document are explicit; every accepted step consumes rows or completes footer/section. No loop without progress.
4. Render the EXACT retained onepage measured renderer (prepare then reconfirm onepage) via one-page UIGraphicsPDFRenderer at existing paperRect/printableRect. To yield between pages safely, combine the generated single-page PDFs with Apple's PDFKit PDFDocument/PDFPage; no graphics context may stay pushed across asynchronous turns. Keep private aggregate document, valid single-page parse checks, title attributes, maximum500pages and20MB final output, final %PDF- signature. On any error/cancel/deadline discard complete partial job; return bytes only after all pages succeed. Release rejected measurement renderers promptly and accepted one after page insertion. Final PDFKit serialization is one synchronous soft-deadline operation checked before/after. No store/network/logged document content.
5. Keep legacy renderPdf and print behavior working; public callback errors remain small stable codes. Extend native fixture for multi-list/empty reports and an oversized single-row case expected to fail cleanly then a short render to prove job release. Preserve primary120Unicode products/360000minor output file so actual pagination is inspected. No gold photo changes.
