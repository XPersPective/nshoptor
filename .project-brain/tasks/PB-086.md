## Objective
“projeyi devral ve tümünü bitir”; PB-065 prerequisite. Google replacement creates a new purchase token; current hash-only identity would reset monthly paid quota.

## Steps
1. In resolveEntitlement, parse existing plain cache policy unchanged or strict JSON {policy,ownerHash}; only known policies and64hex hash. For a freshly verified active subscription, follow Google's linkedPurchaseToken lineage to a prior persisted canonical owner. Expired cache row can supply owner metadata but never active entitlement. Cache current policy/expiry with canonical owner; preserve plain values when owner=current hash. Never accept client-supplied lineage/identity.
2. Uncached parent: use same authenticated Google API to read its linked token; follow at most8 unseen tokens, cycle/deeper/transient failure yields generic503 busy (verified rights are not silently downgraded). If old parent lookup unavailable404/410 and no persisted owner, use its hash as lineage boundary; document lookup retention. Paid identity is token-lineage, not an account/user identity.
3. Canonical owner metadata must survive entitlement expiry/revalidation; no cache-row deletion/cleanup introduced. Retain current policy selection and legacy200/1000, new100/300; preserve existing monthly usage and current-install seed. Read both old/new cache formats; no SQL schema change.
4. Test old→new replacement carries quota across installs and cache expiry;2-step uncached lineage, expired policy metadata does not grant rights, cycles/depth/transient parent failure503, invalid JSON policy/hash never elevates; valid free/canceled state semantics remain PB-082 tests. Worker catches lineage failure without exposing token or lower paid allowance.

## Acceptance
- [ ] Replacement-token monthly usage carries forward to canonical verified owner; legacy/plain cache accepted; expired metadata cannot elevate.
- [ ] Unsupported lineage returns generic busy rather than resetting/downgrading verified quota; no token/content logging.
