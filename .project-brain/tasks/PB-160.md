# PB-160 — Restore reminders without claiming nonexistent native alarms

## Objective
Independent app review found that imported reminders were marked active even though no OS alarm had been scheduled. ID collisions could also overwrite the database target/time while retaining an old native alarm.

## Implementation
Imported active/pending reminders become pendingRestore. Merge preserves an existing native alarm row and assigns a new inactive ID for a conflicting imported reminder. Repeated merge is idempotent. Separate import remaps IDs. Settings keeps localized explicit activation/retry actions visible; import never silently requests OS permission. Permission denial and native failure preserve imported data and retry state. Successful scheduling clears pending copies for that list. Data deletion clears the cached retry UI.

## Limits
Restoring a database does not restore the OS notification queue. User activation schedules the imported reminder with the existing scheduler. A past time uses its existing 30-second future fallback. Native calls that throw after partial OS success remain an explicit scheduler limitation. No formal Project Brain tool acceptance claimed.
