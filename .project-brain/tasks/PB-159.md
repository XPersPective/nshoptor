## Objective
The user explicitly requires iOS as well as Android. Existing purchase code is Google Play only. Add actual StoreKit support and Apple server verification before considering an App Store release.

## Steps
1. Query verified current StoreKit entitlements, not the historical transaction list. Support annual Pro products, purchase, explicit restore, expiration and revocation without breaking Google Play.
2. Transport the signed StoreKit JWS in a separate appleTransaction field. Never interpret an Apple transaction ID or unverified JSON as proof of ownership.
3. Verify Apple signatures, trusted certificate chain, bundle, environment, product, expiry and revocation on the server; revalidate current status with Apple before granting paid quota. Preserve canonical subscription lineage identity.
4. Missing account configuration must fail before consuming quota. Keep secrets server-side, and retain Android verification and legacy ownership.
5. Run focused regressions, analyzer, native iOS compile and integration checks; independently review both native and server changes. Do not equate local fixtures with an actual purchase.

## Acceptance
- [ ] [machine] Annual StoreKit offers and verified current ownership work; expired/revoked/foreign/unsigned data cannot grant Pro.
- [ ] [machine] Invalid configuration or transient Apple verification does not spend Free quota for a purported paid request.
- [ ] [machine] Google Play and trial regressions remain green.
- [ ] [integration] iOS code compiles with the current App Store SDK.
- [ ] [integration] Actual sandbox purchase, restore, refund and expiration are verified using the authorized Apple account.
