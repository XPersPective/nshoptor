### AI reading (PB-186, ADR-008)
- Receipts and shelf labels are read by a vision model from photos in any language or script. ML Kit OCR is only the offline fallback, and it runs lazily.
- **Server:**
  - `server/src/vision_tasks.js` defines the strict protocols `receipt.v2` and `label.v1`, with statuses `complete | top_missing | bottom_missing | middle_gap | not_receipt | unreadable`.
  - Validation covers the schema, row arithmetic (`qty*unit ≈ line ±10 milli`), exact reconciliation (`items = total` or `items − discounts = total`) and tax ≤ total. One corrective retry is free.
  - An echoed status option list counts as `complete` only if the arithmetic holds. A "complete" answer missing store or date becomes `top_missing`; one missing the total becomes `bottom_missing`.
  - Partial statuses return their well-formed visible rows.
  - `server/src/ai.js` takes comma-separated model chains and hedges: the next model starts after 12s for receipts and 10s for labels. The first answer that passes `task.clean` wins, so a wrong answer keeps waiting for the next model.
  - Photos are processed and never stored.
- **Models (Evren, `server/wrangler.jsonc`):**
  - `AI_VISION_MODEL=gemma-4-31b,qwen3-vl-30b,qwen3.8-flash-next`
  - `AI_MODEL=gemma-4-31b,deepseek-v4.1-flash,qwen3.8-flash-next`
  - `AI_NOTHINK=1`
  - Worker `nshoptor-api.devx8585.workers.dev` is deployed with this config.
- **Client:**
  - `lib/features/receipts/ai_receipt_reader.dart` turns the model JSON into canonical rows and feeds them through the existing ReceiptDocument/ReceiptParser, so the deterministic re-verification still runs.
  - `ai_image.dart` resizes to max side 1280 (1600 for tall images). A picker JPEG of 700KB or less is sent as-is.
  - All of a receipt's photos are sent on every request, because the model is stateless.
  - `cleanStoreName()` strips legal suffixes (F29).

### Receipt → list workflow (PB-190, PB-191, PB-192)
- **Header gate:** a first photo without store and date saves nothing (F11).
- **Early list:** the list is created as soon as the header is read, in the receipt currency. Drafts belong to their list, there is no global banner, and stale anonymous drafts are discarded (F12, F13, F15).
- **Receipts section in list detail:** shows store, date, total, and a coloured state (complete, readyToReview, incomplete, failed). From it the user can continue a receipt, or delete it, which allows re-import. A list can hold several receipts (F14).
- **Background reading:** a "Continue in background" dialog lets the user leave; a local notification with payload `receipt-list:<id>` opens the list when reading finishes (F08).
- **Partial receipts:** visible rows are added at once as unpriced items, and the saved receipt links to them with no duplicates (F16).
- **Review:**
  - Lines are accepted by default; the user removes wrong ones (F17).
  - Receipt-only rows never show "quantity changed" (F18).
  - Duplicate rows merge with summed quantity.
  - Discount entries render as a "Discount" row.
- **Receipt date:** shown in the totals card (F19). A completed list counts in History by its latest approved receipt time, not by the day it was finished.
- **Capture tips:** a short tip before the first photo and before each continuation, with a switch in Settings (F05, F06, F38). There is no auto-camera.
- **Speed:** a full receipt reads in about 8s on the server and about 18s end to end on the profile build (F09).
