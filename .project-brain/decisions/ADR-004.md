# ADR-004 — Read-only shopping report snapshots and portable exports
Status: ACCEPTED
Date: 2026-10-25

N033–N038/N041 requires week-first chronological shopping reports, immutable purchase marks, equal home/store price hierarchy and readable exports. The existing editable list detail and system print dialog do not supply that journey. Reuse app theme/localizations and keep charts available in the secondary Insights route. A large horizontal report grid was considered; narrow screens and 2x text instead use wrapping product cards with equally styled price columns (stacked when needed).

## Data contract

ReportPeriod uses local calendar day/week/month/year/custom boundaries with an exclusive end. Week begins Monday. Completion time remains the historical aggregation date, consistent with existing InsightsRepository; list creation, shopping completion and observed printed receipt time are displayed separately. No invented purchase date, exchange rate or receipt metadata is supplied.

ReportRepository reads one transaction, completed lists newest-first and one currency. Only confirmed purchase entries and reviewed receipts enter the snapshot. Explicit free prices remain known; missing prices remain unknown rather than zero. Multiple entries aggregate actuals while counting a planned estimate once; discounts and unplanned purchases survive. Data queries batch list IDs in groups of400 rather than one query per shopping list. Report models expose no mutation method; ticks use read-only semantics.

## UI/export states

History starts with the current week and shopping headings, with explicit day/week/month/year/custom controls, calendar jump and currency selection. Loading, empty and retryable failure remain visible. A report preview reflows with explicit zoom; export is idle or busy, with save/share disabled and pop guarded while active. Cancellation returns without changing purchases or claiming a saved file; failure presents a short dismissible message and allows retry. PDF/CSV are derived from the same captured snapshot. CSV uses UTF-8 BOM, quoted cells, formula-safe user text and canonical decimal money. No XLSX support is claimed.

## Native PDF choice and limits

Android public SDK does not expose PrintDocumentAdapter result callback constructors for application-driven byte rendering. Hidden API/reflection approaches were rejected. Existing system printing remains available to its previous caller. New renderPdf uses public PdfDocument and StaticLayout, structured localized text from the same snapshot, A4 pagination, Unicode/bidi, repeating title/page number and paragraph grouping. It preserves report values but does not reproduce the HTML table styling. iOS uses the existing bridge extended with UIMarkupTextPrintFormatter/UIPrintPageRenderer and UIGraphicsPDFRenderer, with A4 geometry overrides rather than KVC.

Native inputs are bounded to2M characters/title200; output is bounded to500pages/20MiB and a30s deadline (Dart35s). Android owns native/file resources on its worker and uses one-shot main-thread result/lifecycle cancellation; private cache output is removed in finally. UIKit pagination is synchronous on main and cannot be interrupted mid-call; Windows source review cannot establish iOS responsiveness or compilation. Actual iOS verification remains open.

This ADR is a design decision, not acceptance. Native rendering, save/share cancellation, RTL/large text visual inspection and independent final review remain verification gates in PB-147.
