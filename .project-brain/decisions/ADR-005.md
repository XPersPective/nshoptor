# ADR-005 — First-install Pro trial independent of store purchases
Status: ACCEPTED
Date: 2026-10-25

N049–N053 requires the first7days of full Pro without purchasing an introductory store offer. Existing AdGate grants only ad-free grace; paid-offer trial flags do not create this entitlement. Preserve actual store ownership/credentials and distinguish it from promotional access. Trial must never manufacture a purchase token, change a paid product, or reset monthly usage.

## Authority and identity

Reuse the random32hex installation identity already sent to the AI service. A new bounded /v1/access registration records one immutable-or-earlier seven-day window per identity in D1. The server clamps an optional earlier local first-open hint to server time; future/repeated registration cannot extend the deadline. The earliest surviving legacy first-open/ad-policy anchor prevents upgrades or restored local state from manufacturing a new first week. Clock rollback cannot reactivate a window after its later observation.

Existing clients that never register retain their Free10 policy. New clients register before AI tasks; active registered trials receive the same100/month policy as current annual Pro. AI success/failure/expiry continues using the existing installation/month counter and atomic global budget. Expiry lowers the allowance without clearing usage. Verified paid token lineage retains its existing higher/legacy policy and canonical quota identity. Trial registration never calls the AI provider and consumes no AI quota.

Local promotional access supports offline core/backup use and displays an explicit remaining duration, while the server remains authoritative for AI. It shares the original first-open clock with ad-free grace. Billing ownership and promotional access are separate properties so restore/replacement/buy logic still acts on real purchases. One persisted expiry notice offers annual Pro and an explicit Free continuation once; it does not loop on every launch.

## Limits and deployment

An anonymous installation ID cannot prevent a fresh identity after all app data is erased/reinstalled. State this honestly; do not claim access to the Play user's personal identity, an unresettable hardware ID, or perfect anti-abuse. A copyable support ID may derive from the existing random identity; raw purchase tokens never enter UI/logs/support messages.

The new table is additive. Apply/read back migration before enabling new worker code, then test registration/AI policy without spending provider requests. Existing app counters, paid ownership and user data are preserved. A feature flag provides deployment ordering, not a permanent promise that an unregistered client has100AI. Current app/store/catalog remains annualUSD1 before tax and localized final store pricing.

This records the implementation contract, not completion. Remote deployment/readback, real purchase/restore, offline/clock/reinstall limits and native localized UI remain PB-150 gates. No Evidence/Review acceptance is inferred.
