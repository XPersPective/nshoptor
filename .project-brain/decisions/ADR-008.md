# ADR-008 — Receipts and shelf labels are read from photos by an image model

Status: ACCEPTED (user decision 2026-10-28)

## Context
On-device ML Kit reads only some scripts (no Arabic) and has no understanding of layout,
so rule-based parsing cannot serve every country's receipts. The user requires reading
that works in every language, guides the user through partial receipts and never
accepts a wrong result, independent of which AI model runs behind the server.

## Decision
- Photos (downscaled to 1600 px JPEG, ≤700 KB each) go to the Worker when AI is on; they
  are processed immediately and never stored or logged. Privacy texts say so.
- Protocols `receipt.v2` and `label.v1` (`server/src/vision_tasks.js`) are model-agnostic:
  strict JSON, ASCII digits, status codes (`complete`, `top_missing`, `bottom_missing`,
  `middle_gap`, `not_receipt`, `unreadable`). Model is `AI_VISION_MODEL` (else `AI_MODEL`).
- Acceptance layers: server schema + row arithmetic + exact reconciliation with one free
  corrective retry; client re-verification; rebuilt local document must reproduce every
  line, discount and total; user review before any write.
- The model is stateless. The phone keeps all photos of a receipt as a draft and sends all
  of them on every request, so no part is lost. Status codes drive guided continuation;
  unfinished receipts are announced on the main screen.
- Device OCR + rule parser remain the offline / over-quota fallback.
- Warnings are codes mapped to localized app strings, never model-written text.

## Consequences
Play Data safety and App Store privacy labels must declare photos as processed
(ephemeral, not stored). Live model accuracy must be measured on real receipts before a
public release.
