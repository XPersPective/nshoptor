# ADR-002 — Production scope and recoverable delivery
Status: ACCEPTED
Date: 2026-10-23

The user explicitly requests implementation, verification and publication of the full shopping product, a free GitHub website, Android/iOS readiness and a durable handoff. Their verbatim request and all fifty requirements are in .project-brain/references/production-master-prompt-tr.md. This supersedes ADR-001's publication exclusion: Brain tracks publication intent/readback; release tools perform external store operations.

Keep Flutter/Drift, fixed-point money, native local speech/OCR and the existing kit. Reuse the kit's bounded/catalogue cache and review policy; add app-owned platform filtering instead of modifying cached vendor files. A curated apps.json update is automatic catalogue refresh, not arbitrary store crawling.

Use market-price presence, including explicit zero, as the purchase invariant. A missing price remains unknown. Keep unavailable/gave-up distinct. Ambiguous multi-item prices require a short explicit choice; confirmed market prices route to the actual purchase and must not silently change currency.

Keep list reminders local, with no network service or Firebase charge. FCM is a possible free remote-delivery service only if remote notifications become necessary. Workers/D1 must respect free-tier limits; existing Qwen token-plan use is not proof of a free AI provider. No paid fallback or billing change is authorized.

Order work: durable scope/baseline → core shopping flow → voice/OCR → help/history/reports → notification/service boundaries → marketing/platform release gates. Website deployment can be verified independently. Store internal test, review submission and public production remain distinct.

Alternatives rejected: rewriting the architecture; scraping all stores; silently adding cloud accounts/sync; treating unit tests as live camera, microphone, billing or iOS proof; marking provider price permanence as guaranteed.

Planning consolidation preserves original task texts under .project-brain/history/2026-10-24-consolidation/planning-2026-10-23: PB-101→105, PB-103→122, PB-104→125, PB-106→105, PB-109→110. Added PB-126..130. The 2026-10-23 snapshot had twenty-five active tasks; later user intake adds scope without claiming consolidated tasks completed. PB-155 records the recoverable source migration and restored acceptance criteria.

Pool readback: Claude OAuth failed; MiniMax job reported file tools unavailable despite succeeded wrapper; ZCode timed out with needs_review and no matching settings diffs. No failed write was blindly replayed. Native bounded workers then implemented isolated areas. Two native workers later reached account usage limits; their unfinished work is inspected before takeover. Existing PB start/check records belong to their original digest; they are not proof for subsequent native changes. A stale legacy pool-approval gate rejected local-implementation bookkeeping; acceptance/review records must not be fabricated or bypassed.
