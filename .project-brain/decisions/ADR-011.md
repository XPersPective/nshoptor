# ADR-011 — Capture-First Background Receipt Queue, Theme Harmony & UI Proportions
Status: ACCEPTED
Date: 2026-11-13

## Context
User directive `RQ-002` (2026-11-13) identifies critical UX and architectural gaps after release `1.3.3+30`:
1. Receipt scanning blocks the UI while OCR/AI runs, forces client ML Kit as the primary path instead of Server Vision AI, and cannot queue rapid back-to-back multi-receipt sessions across app backgrounding/closure.
2. There is no dedicated `Fişlerim` queue/tray with unconverted count, no `(store + date + time)` duplicate guard before list creation, and no quick photo reference inside the resulting shopping list. Shelf label scanning (`Etiket okuma`) must follow the same non-blocking Server Vision AI primary rule.
3. Dark surfaces (`#07140E` / `#040D09`) feel overly pitch-black, action buttons (`Yeni Liste`, `Fişten Listeye`) feel overly saturated, the `ListsScreen` AppBar mixes oversized `?`/`Discover` icons with an undersized `Free`/`Pro` pill, the tab-bar cycling `sortButton` is clunky, and `SettingsScreen` mixes inconsistent typography, weights, and alignments.

## Options Considered & Chosen Design

### 1. Cross-Platform Background Queue (`Android + iOS`, C-006 compliant)
- **Option A (`workmanager` pub plugin):** Adds heavy plugin dependency and risks iOS `BGTaskScheduler` SQLite/isolate lock contention. Rejected (`C-006`).
- **Option B (Pure in-process Isolate + Resume-Reconcile):** Zero dependencies, safe single Drift connection, but stalls when OS suspends/kills the app right after capture before firing the *"Fiş hazır"* notification.
- **Chosen — Hybrid B + Thin Native Wake Channel (`nshoptor/background_queue`):**
  - Persistent Drift queue (`Receipts` table) + singleton `ReceiptQueueService` draining sequentially inside the active isolate while the app runs.
  - **Thin native platform hooks (zero new pub plugins):** On iOS, `UIApplication.beginBackgroundTask` extends immediate background runtime plus `BGProcessingTaskRequest` (`com.crazypenguin.nshoptor.receipt-queue`, network required) wakes a headless `FlutterEngine` if suspended. On Android, a native `androidx.work.CoroutineWorker` (`NetworkType.CONNECTED`) kicks the live engine if in-memory or launches a headless `FlutterEngine` (`@pragma('vm:entry-point')`) when killed, guarded by an in-process single-engine lock to guarantee single-writer SQLite safety.
  - App launch and `AppLifecycleState.resumed` run `reconcileAndDrain()`, resetting stale interrupted `processing` rows to `queued` so zero captures can ever strand.
  - Completion fires a `flutter_local_notifications` notification (`receipt-draft:<id>`) that opens `Fişlerim` / review when tapped.

### 2. Receipt State Machine, Drift v6 & `(store + date + time)` Deduplication
- **Schema Migration (`schemaVersion: 6`):** Extend `Receipts` cleanly with non-breaking nullable/default columns: `queueState` (`captured | queued | processing | ready | duplicate | error | converted`), `queueError` (nullable short code), `convertedAt` (nullable `DateTime`), `duplicateOfListId` (nullable `Int`, `onDelete: setNull`), and an index on `(listId, queueState)` for reactive `"Fişlerim (N)"` badge counts (`listId IS NULL AND queueState != 'converted'`, plus `ready`/`duplicate`/`error` items until user dismisses). Wait: also keep unconverted vs converted deletion semantics clean — deleting a converted receipt from `Fişlerim` unlinks/removes the receipt photo/record per existing `ReceiptRepository.delete` or hides from `Fişlerim` while keeping user-controlled delete updating `(N)`. Specifically, keeping a `dismissedFromTray` / delete action guarantees `Fişlerim` only counts active/unconverted receipts in `(N)` while offering explicit deletion anytime.
- **Capture-First Flow:** Capture screen asks **only** *"Same receipt continue (next page)"* or *"Done"*. Pressing *"Done"* compresses pages to compact legible JPEG bytes (via `ai_image.dart`), persists the unique session row, schedules background work, and exits immediately so the user can scan the next receipt without waiting.
- **Server Vision AI Primary:** Queue sends compact JPEGs to `/v1/ai` (`read_receipt_image` / `read_label_image`). Local ML Kit runs **only** as an explicit offline / AI-disabled fallback.
- **Deduplication (`C-004`):** When AI completes, normalize `store` (alias/whitespace/punctuation folded) + `printedAt` within a ±15 minute window (or same calendar day when time is omitted) against existing lists & receipts. Matches transition the draft to `duplicate` (with `duplicateOfListId`) and warn *"zaten bu fiş girildi"*, letting the user explicitly choose **Discard/Delete** or **Convert anyway**.
- **Conversion & List Attachment (`C-004`):** *"Listeye Çevir"* opens `ReceiptReviewScreen` for explicit user approval. Saving creates/updates the list inside a Drift transaction and retains the compressed receipt photo(s) at the bottom of `ListDetailScreen` with an interactive photo viewer.

### 3. Eye-Friendly Theme Variations, Balanced Buttons & UI Hierarchy
- **Dark & Light Palette Variations:** Replace pitch-black dark surfaces (`#07140E` / `#040D09`) with comfortable slate/charcoal-tinted dark surfaces (`#121614` / `#181F1B`, etc.) paired with refined `AppPalette` options (adding warm/calm variations alongside curated `forest`, `ocean`, `sunset`, `lavender`), while keeping pure AMOLED `#000000` strictly as the explicit Settings opt-in (`darkBlack`) and keeping `#0B8457` brand identity (`C-007`).
- **Harmonious Action Buttons:** Tune `FilledButton` / `FilledButton.tonal` / `OutlinedButton` container tones across all palettes so primary CTAs (`Yeni Liste`, `Fişten Listeye`) maintain calm visual balance and WCAG AA (`>= 4.5:1`) contrast without harsh glare.
- **AppBar, Sort & Typography Unification:**
  - `ListsScreen` AppBar: `?` and `Discover` at balanced `24dp` icons in `48dp` touch boxes beside a `32dp`-tall balanced `PlanBadge` pill.
  - Sort control: replace the tab-bar cycling `IconButton` with a compact right-aligned tonal filter/sort menu chip (`PopupMenuButton` / `MenuAnchor`).
  - Settings & App-Wide Hierarchy: uniform `16dp` horizontal list insets, `titleMedium` (`w600`) primary labels, `bodyMedium` subtitles, and aligned `labelMedium` value chips (`Pro`, `TR`, `Adet`, `Türkçe`, `Cihaz seçimi`).
