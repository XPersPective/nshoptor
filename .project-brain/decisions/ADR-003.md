# ADR-003 — Durable receipt evidence and approval boundary
Status: ACCEPTED
Date: 2026-10-25

The user's N005–N014 requires recoverable partial scans, complete receipt identity and one purchase effect across retries. Reuse the existing Receipts, ReceiptCandidateLines and PurchaseEntries.receiptId tables. Alternatives were in-memory-only capture (loses progress on restart) and opaque AppSettings/rawOcrText payloads (mixes configuration/plain text with structured state). Neither satisfies the existing data boundaries. No account, server image upload or new AI route is introduced.

## States and transitions

- Acquisition produces CapturedImage, CaptureCancelled or a typed CaptureFailed stage. Owned ML Kit sources are closed; injected sources remain caller-owned. A cancellation or permission failure ends acquisition without forced retries.
- ReceiptDocument is immutable OCR evidence. incompleteHeader records missing merchant/date+printed time/document number/currency; incompleteTail records missing products or final total. complete means observed coverage, and approval additionally requires the fixed-point product/discount sum to reconcile within the parser tolerance. Unknown header values are never invented.
- A continuation must have one unambiguous ordered product suffix/prefix overlap and no conflicting known document metadata. Header recovery prepends; tail recovery appends. Repeated products remain ordered purchases. Financial rows in the observed overlap are replaced as a span, so distinct earlier discounts survive and repeated discounts count once.
- A version1 bounded JSON capture (2 million characters,25frames,10,000rows) replays original OCR fragments on restart. It does not trust a stored complete flag. Draft pending saves create no shopping list, purchase or price observation and reserve no identity. This is the user-authorized N012 exception to the older blanket wording about no preapproval writes.
- Review begins with local matching; optional AI enrichment cannot delay approval or override an accepted/ignored/explicitly unlinked row. Review phases are matching, ready and saving. Every strict review row must be accepted or explicitly ignored. A selected subset needs a separate confirmation that the receipt will be marked imported.
- Final approval reserves a global unique receipt identity, stores reviewed candidate decisions, links purchases and updates the list in one transaction. A fresh receipt creates a separate planned/purchase row when the matched row already has a market price, including legacy/explicit zero. Existing prices/observations are preserved. An unpriced row can be filled only once per receipt; repeated rows still produce separate purchases.
- A committed identity read back after a transaction conflict produces ReceiptAlreadyImported. A failed transaction leaves no partial list, candidate, identity or observation, and permits a retry. A changed/superseded draft cannot be approved using stale evidence.

## Media and recovery

Picker files are copied to the app-owned flat receipt_media directory before draft save. Copy/save failure removes only the newly generated owned file; a successful retake removes superseded files only after checking remaining receipt references. Deletion rejects arbitrary backup paths, unrelated names and resolved paths outside that directory. Delete-all receives this directory from main. The existing JSON backup carries OCR capture data and image paths; it does not embed image binaries. Invalid capture JSON and duplicate receipt identities reject before import writes; a duplicate separate-copy import is atomic failure, not identity erasure.

The controller's legacy document=null entry is retained for earlier programmatic/parser tests and explicit replacement callers. All actual home/list camera entry points use the strict document/draft path. Removal of the legacy seam is possible after its old callers/tests are separately migrated; it is not a bypass exposed in the product.

## Verification limits

Review followup2026-10-25: metadata uses geometry-reconstructed reading rows; quantity×price continuations retain their preceding name. Continue never implicitly discards images; only explicit retake can replace them. Merge of an older pending receipt backup cannot downgrade a committed identity/evidence. AI enrichment is tied to immutable input snapshots and discarded after structural/content edits. Foreign currency evidence rebases earlier context-only fragments and survives prepend/replay. Identity v2 uses merchant/document number/printed date+minute/currency, while full observed seconds remain metadata; old v1 keys are recomputed from retained evidence during duplicate preflight. A merchant label is still not a branch identifier, and arbitrary OCR errors cannot be made perfectly identity-safe without a broader real receipt corpus.

This ADR records the chosen architecture, not task completion. Current source is under focused/full, visual/accessibility and native verification. Header heuristics and timestamp/merchant precision need a realistic multilingual corpus. Synthetic OCR, a successful build and a home screenshot cannot prove camera robustness or native stability. PB-141,PB-142 and PB-156 retain those open gates; no formal Evidence/Review/accept is handwritten.
