# ADR-007 — Measure complete iOS report rows before pagination
Status: ACCEPTED
Date: 2026-10-27
Domains: reports,native-state

## Context
Actual UIKit PDF artifacts split/clipped products across pages and did not repeat table headings. Adding both modern and legacy CSS break avoidance did not fix the nine-page,120-product baseline. Correct byte generation and test success did not establish readable output. Evidence remains privately under artifacts/qa/2026-10-27/PB-147/6833146/native.

## Decision
- One immutable escaped Dart report-fragment model generates ordinary HTML and version1 native pagination data. Android text/CSV and ordinary HTML contracts stay intact.
- iOS measures complete candidate pages with the same A4 geometry and UIKit formatter used for drawing. Every accepted candidate must have exactly one page; never draw only page zero of a multipage candidate.
- Fixed table layout/header geometry makes whole-row prefix fitting monotonic. Repeat document/list context and table headings explicitly. Try final rows with totals first; otherwise fit a prefix without totals. A measured footer-only page is allowed; an oversized individual row/header/footer fails explicitly.
- Main-queue work yields between measurements and one-page drawings. Merge those PDFs with Apple's PDFKit, avoiding a live UIKit graphics context across asynchronous turns. No third-party renderer or hand-written HTML parser.
- Generation/job identity, application activity,30second soft deadline,500pages,20MB final bytes and typed/bounded input protect the existing single-result lifecycle. A single UIKit/PDFKit call cannot be preempted; check before/after it. Failed/cancelled jobs return no partial document.

## Consequences
- Reports may use more pages because context/headers repeat; readability and complete rows take priority over compact page count.
- Keep candidate fonts/column widths/geometry identical. Changing these requires renewed prefix-fit and actual native PDF inspection.
- Inspect every page boundary, unique product counts, Unicode/RTL and totals, plus empty/multiple/oversized/retry cases. Widget renders and PDF signatures cannot replace this evidence.
- Production uses the ordinary entrypoint; isolated debug native UI QA uses synthetic data and the real exporter. Store screenshots and physical-device/VoiceOver proof remain separate.
