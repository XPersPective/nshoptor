# ADR-007 — Preserve paid AI allowances while introducing new offers
Status: ACCEPTED
Date: 2026-10-10

## Problem and evidence
PB-065 proposed replacing Pro200/Max1000 with 100/300. tool/play/subscriptions.rb lists 200/1000 benefits on existing nshoptor_pro/nshoptor_max; current server maps only tier, so changing those limits silently cuts existing promises. The user authorized completion and explicitly retained the present Qwen Token account.

## Options
1. Replace old SKU limits: violates compatibility requirement.
2. Grandfather by Google startTime cutoff: extra cohort inference; old client continues offering old benefits on those same SKUs to new buyers.
3. New nshoptor_pro_v2/nshoptor_max_v2 offers, recognize old SKUs on restore, preserve old benefits: explicit product boundary.

## Choice
Option3. New offers Free10/Pro100/Max300 monthly; existing paid SKUs stay 200/1000. Annual uses the same monthly allowance; lifetime retains ads/backup and Free AI. Do not deactivate or rewrite old product benefits. Clone verified prices/regions into new offers; never purchase in production QA. Server recognizes both policies; HTTP tier remains free/pro/max. Existing plain pro/max cache values mean legacy policy. Retain current provider endpoint/model/secret by user choice.

Quota claims use an atomic D1 batch; paid counters use SHA256 of the verified token rather than resettable installation ID. No raw token or content logging. Free identity remains resettable; daily global cap is the known ceiling. New replacement tokens require an explicit tested carry-forward policy in rollout; do not claim account-level identity without accounts.
